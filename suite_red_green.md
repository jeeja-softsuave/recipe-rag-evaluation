# Week 11: the suite, RED before the fix and GREEN after

**The suite** is the Week 6 suite plus the Week 11 cases:
- the 34 cases in `substitution_cases.jsonl`, plus `w11-01` and `w11-02` from `eval_cases_week11.jsonl`;
- all 6 deterministic checks in `assertions.py`: the Week 6 five, plus the new `dairy_free_swap_is_safe`.

Every case is regenerated through the production app (`observe.py`) at the prompt version
under test. The full suite is rerun every time, so a fix that breaks another case cannot hide.

| Run | Prompt | 6 assertions | **Assertions + judge** | `w11-01` | Notes |
|---|---|---|---|---|---|
| baseline | v1 | 32/36 | 31/36 | pass (refused) | the version before the helpfulness change |
| **RED** | **v2** (production) | 26/36 | **25/36** | **FAIL** (assertions and judge) | the failure, watched before any fix existed |
| fix attempt 1 | v3 | 29/36 | 26/36 | FAIL | not green: **s07 and r09 newly failing**, w11-02 newly failing |
| **GREEN** | **v4** | 36/36 | **33/36** | **pass** (assertions and judge) | released as a 10% canary, not to production |

**The 3 cases v4 still fails with the judge are not caused by v4.** s18 fails on every
version: it is Week 6's derived-number case (halving 3 g to 1.5 g), which no prompt
version addresses. r06 and r09 are refusals that the judge calls wrong on some versions and
not others (r06: v1 assertion fail, v2 pass, v3 and v4 judge fail; r09: v1 pass, v2 judge
fail, v3 assertion fail, v4 judge fail). r09 is the case whose label Week 6 found contestable.
They are follow-ups for the judge and the refusal rule, not regressions v4 introduced.

**Ordering:** the RED outputs file was finished at 21:19:14 local (IST) on 2026-10-08.
v3 was written after that and finished at 21:27:20; v4 finished at 21:35:16. No fix existed
when RED ran.

**Model caveat.** The production log runs `gemini-3.6-flash`. These suite runs use
`gemini-3.5-flash-lite` for every version, because the 3.6 Flash free quota was exhausted
for the day. The comparison between versions is fair (same model throughout), but it is
measured on a smaller model than production. **The judge** is `judge_v2`, word for word,
but run on `gemini-3.5-flash-lite` rather than Week 6's `gemini-3.6-flash`. On 2026-10-09,
3.6 Flash was still refused on every key (account-level cap), so the ruler's prompt is the
same but its model is not. Every version was judged by the same flash-lite judge, so the
four columns are comparable with each other; they are not comparable with Week 6's 94%.

**A note on file names:** the v3 run was started with `--label green`, expecting it to pass. It
did not, so `suite_report_green.json` is the **failed** v3 attempt. The passing run is
`suite_report_green_v4.json`. I left the file names as they were run, rather than renaming
evidence after the fact.
